# 8장: 프로세스 실행하기 — 팀과 함께, 끝까지

## Core Idea
대화를 감싸는 프로세스가 엉성하면 좋은 질문도 형편없는 결과를 낳는다. 핵심은 배움이 한 사람의 머릿속에 갇히는 '학습 병목'을 막는 것 — 준비하기, 복기하기, 메모 잘하기로.

## Frameworks Introduced
- **학습 병목 (learning bottleneck)**: 사업 담당자 혼자 미팅을 독점하고 "고객이 그랬다니까"라는 무적 카드로 팀을 통보하는 상태. 저자의 CTO는 "당신이 계속 우리가 할 일을 바꾸면 우린 절대 성공 못 해"라며 퇴사했다 — 배운 내용이 사실이어도 전달에 실패하면 소용없다.
- **전체 프로세스 (미팅 전/중/후)**:
  - **전**: 좁고 찾기 쉬운 세그먼트 선택 → 팀과 3대 학습 목표 결정 → (해당 시) 이상적 다음 단계·약속 결정 → 누구와 이야기할지 결정 → 상대가 신경 쓰는 것 최선의 추측 작성 → 책상 검색으로 답할 질문은 미리 해결
  - **중**: 틀 잡기 → 가볍게 → 맘 테스트 통과 질문 → 칭찬 흘리기·빈말 닻 내리기·신호 파기 → 메모 → (해당 시) 약속·다음 단계 밀어붙이기
  - **후**: 팀과 메모·핵심 인용 복기 → 메모를 영구 저장소로 → 믿음·계획 업데이트 → 다음 3대 질문 결정
- **메모 기호 12종**: 감정 — `:)` 신남, `:(` 화남, `:|` 민망함 / 삶 — `⚡` 고통·문제, `⨅` 목표·JTBD, `☐` 장애물, `⤴` 임시방편, `^` 배경·맥락 / 구체 — `☑` 기능 요청·구매 기준, `＄` 돈·예산·구매 절차, `♀` 인물·회사 언급, `☆` 후속 작업. 강한 감정 + 고통/장애물 조합에 가장 무게가 실린다.
- **숨은 리스크 준비 질문 2종**: "이 회사가 망한다면, 무엇이 죽일 가능성이 가장 클까?" / "엄청난 성공을 거두려면 무엇이 참이어야 할까?" — 결국 알아내려는 건 "이 사람들한테서 뭘 배우고 싶은가?" 하나. 시간이 빠듯하면 이 질문 하나가 준비의 전부.

## Key Concepts
- **누가 나가야 하나**: 큰 결정을 내리는 팀원은 누구든 몇 번은 나가야 한다. 미팅은 2명이 최적(한 명은 메모, 한 명은 대화; 서로의 실수·편향 교정). 3명 이상은 압도적. **배움의 외주 금지** — 고용인은 나쁜 소식을 얼버무리고 싶어진다. 반복 가능한 영업 프로세스 전까지 창업자가 직접 방에 있어야 한다(진행은 남에게 맡겨도 됨).
- **메모의 조건**: 분류·재배열 가능 / 팀원 메모와 병합 가능 / 영구 보존·재검색 가능 / 할 일·아이디어 소음과 분리. 정확한 인용은 따옴표로 — 마케팅 문구, 투자 자료, 팀 내 다툼 정리에 쓰인다.
- **메모 매체**: 스프레드시트·에버노트(공유·정렬 탁월, 옮기는 후작업 필요), 저자 최애는 **인덱스카드**(카드 1장 = 인용·배움 1개 + 기호, 복기 때 펼쳐놓고 분류·재정렬). 음성 녹음은 정렬·검색이 안 돼 결국 안 듣게 됨. 녹음 요청 멘트: "메모에서 중요한 걸 놓칠까 봐 불안해서요. 아무한테도 공유 안 할게요."
- **그냥 후려쳐라 (Gordian Knot)**: 개인 트레이너에게 "경찰이 더 나은 고객일지" 검증 방법을 다들 신나게 설계하는데, 그가 휴대폰을 들고 "그냥 전화하면 안 돼요?" → 20분 뒤 무료 체험 세션 확보. 프로세스에 갇히지 마라.
- **속도 규율**: 미팅 준비는 1시간(그 이상은 시간 끌기), 풀타임 고객 대화는 1~2주(그 후엔 약속할 무언가를 내밀어라). 어떤 고객 질문이든 일주일 안에 답하고 다음으로. 사업 키우기를 멈추고 하는 게 아니라 나란히 한다.

## 시늉만 하고 있다는 징후 (자가 진단)
상대보다 내가 더 말함 / 상대가 나·아이디어를 칭찬함 / 아이디어를 말했는데 다음에 뭐가 일어날지 모름 / 메모 없음 / 팀과 메모 안 봄 / 예상 밖 답을 들었는데 아이디어가 안 바뀜 / 무서운 질문이 하나도 없었음 / 어떤 핵심 질문에 답하려는 건지 모름 → 하나라도 끈질기게 남아 있으면 시간 낭비 중.

## Worked Example
**복기하기의 실제**: 대화 후 팀과 메모를 훑으며 믿음과 3대 질문을 업데이트. 핵심 인용과 주요 시사점 공유 + **메타 복기**("어떤 질문이 통했고 뭐가 안 통했나? 다음엔 어떻게 더 잘할까? 놓친 신호는?"). 준비·복기 모두 단계라 부르기 민망할 만큼 단순해서 건너뛰고 싶어진다 — 건너뛰지 마라. 이것이 배움을 종이 위에, 그리고 모두의 머릿속에 넣는 유일한 장치다.

## Anti-patterns
- **"고객에게서 배우기" 체크박스용 설문**: 대충 만들어 뿌린 설문은 시늉일 뿐. 도움이 안 될 것 같으면 대화 자체를 건너뛰어도 된다 — 도구이지 의무가 아니다.
- **"코딩해야 한다고!"**: 겉은 현실 부정 같지만 실은 속도를 향한 욕망 — 다만 그 속도를 리스크 감소가 아니라 기능 산출로 재는 게 문제.
- **실수 자책**: 저자도 어제 자랑 모드로 미팅 하나를 망쳤다. 팀으로 복기하되 들볶지 마라. 나쁜 대화는 대부분 고칠 수 있다.

## Key Takeaways
1. 무엇을 배우려는지 모르겠다면, 그 대화는 아예 하지 마라.
2. 들여다보지 않는 메모는 쓸모가 없다.
3. 병목을 만들지도, 병목이 되지도 마라 — 배움을 빠르고 충실하게 팀 전체에 퍼뜨려라.
4. 프로세스는 가치 있지만 갇히지 마라. 때로는 그냥 전화기를 들어 매듭을 후려쳐라.
5. 잔말 말고 어서 가서 당신 회사나 만드세요.
