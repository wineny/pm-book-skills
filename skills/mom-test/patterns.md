# 기법 & 패턴 — 더 맘 테스트

## 맘 테스트 질문 변환
**When to use**: 모든 초기 고객 대화에서 질문을 설계·교정할 때
**How**: 아이디어/미래/의견 질문 → 상대의 삶/과거/사실 질문으로 변환. "사시겠어요?" → "지금은 어떻게 해결하세요? 비용은? 마지막으로 그 문제가 불거졌을 때 얘기를 처음부터 끝까지 들려주세요."
**Trade-offs**: 편향은 없지만 사소한 질문만 하게 될 위험 → 중요한 질문(3장)과 결합 필수

## 칭찬 흘려보내기 (deflect)
**When to use**: "정말 멋지네요, 마음에 들어요"가 나올 때 (거의 모든 대답에 섞여 있음)
**How**: 사과+화제 전환: "앗, 제가 자랑을 늘어놨네요. 요즘 이런 건 어떻게 처리하고 계세요?" 칭찬은 기록하지 말고 사실·약속만 수집
**Trade-offs**: 칭찬 무시는 생각보다 어렵다 — 듣고 싶은 말이라 긍정 데이터로 착각하기 쉬움

## 빈말에 닻 내리기 (anchor)
**When to use**: "항상/보통/절대/~할 거예요/~할지도"가 들릴 때
**How**: "마지막으로 그게 언제였어요?" → "그때 얘기 좀 들려주실래요?" → "어떻게 해결하려 했어요?" → "다른 해결법을 검색해봤어요?"
**Trade-offs**: 빈말 유발 질문 자체는 무해 — 구체 질문으로 넘어가는 토스로 활용 가능. 답을 믿는 게 잘못

## 아이디어/감정 밑 파고들기 (dig)
**When to use**: 기능 요청이 나오거나 강한 감정(분노·민망·환희)이 보일 때
**How**: 기능엔 "왜 원하세요? 그게 되면 뭘 할 수 있죠? 없는 지금은 어떻게 버티세요?" / 감정엔 "그 얘기 좀 더 들려주세요. 뭐가 그렇게 끔찍하던가요? 왜 아직 못 고치셨어요?"
**Trade-offs**: 요청을 할 일 목록에 직행시키면 기능 과잉行. 이해하되 따르지 마라

## 중요성 검증 (진통제/비타민 판별)
**When to use**: 문제가 '돈 낼 문제'인지 '감당되는 짜증'인지 애매할 때
**How**: "그게 어떤 영향을 미치나요?" + 진지함 질문 세트(돈 버나, 시간 얼마나 쓰나, 개선하려 이미 뭘 하나, 3대 우선순위에 드나)
**Trade-offs**: 불평의 볼륨과 문제의 심각성은 별개 — "재앙이에요!"라던 사람이 영향을 묻자 "사실 꽤 잘 굴러가요"

## 약속 요청으로 검증
**When to use**: 제품/아이디어를 공개한 이후의 모든 미팅 마무리
**How**: 시간(다음 미팅, 시험 사용)·평판(상사·팀 소개, 사례 연구)·돈(LOI, 선주문, 보증금) 중 지금 요청 가능한 것을 밀어붙인다. 흐릿한 약속("준비되면 소개")은 구체화 질문으로 전환
**Trade-offs**: 거절당할 수 있다 — 하지만 거절은 데이터, 묻지 않음이 진짜 실패. 시험판이 너무 '싸면' 비용을 올려라

## VFWPA 미팅 요청 (Very Few Wizards Properly Ask)
**When to use**: 정식 미팅이 불가피할 때 (1시간 필요, 인맥 밖 윗사람)
**How**: 비전(아이디어 언급 없이) → 틀 잡기(팔 게 없음 명시) → 약한 모습(막힌 문제 고백) → 치켜세우기(당신이라서 도울 수 있다) → 부탁. 미팅 시작 시 반복하고 곧장 첫 질문으로 고삐를 쥔다
**Trade-offs**: 피치처럼 들리면 스팸 취급 — 약점 고백을 앞으로 당겨라

## 고객 슬라이싱
**When to use**: 피드백이 사방으로 튀거나(대화 10건+에도 제각각), 어디서 시작할지 모를 때
**How**: "이 그룹에서 누가 가장 원하나? 왜? 그 동기의 다른 소유자는? 그들은 이미 뭘 하고 있나? 어디서 찾나?"를 반복 → 누구-어디 짝 도출 → 수익성·접근성·보람으로 선택
**Trade-offs**: 좁힘은 임시 — 나중에 넓힐 수 있다. 연락 닿을 수 없는 세그먼트는 무용

## 숨은 리스크 사고 실험
**When to use**: 미팅 전 준비, 3대 질문 선정 시
**How**: "이 회사가 망한다면 뭐가 죽였을까?" + "엄청난 성공에는 무엇이 참이어야 할까?" → 나온 요소를 알아낼 질문 설계. 제품 위험/시장 위험 구분 후 대화로 답할 수 있는 쪽만 대화로
**Trade-offs**: 직감 반응이면 충분 — 길고 엄밀한 전략 토론이 아니다

## 인덱스카드 메모 + 기호 체계
**When to use**: 모든 고객 대화의 기록과 팀 복기
**How**: 카드 1장=인용·배움 1개+기호(⚡고통 ⨅목표 ☐장애물 ⤴임시방편 ^맥락 ☑구매기준 ＄돈 ♀인물 ☆후속 + 감정 :) :( :|). 미팅 후 날짜·이름 기입, 복기 때 펼쳐 분류
**Trade-offs**: 어디 적었든 영구 저장소로 옮기는 후작업 필요. 음성 녹음은 검색 불가로 사장됨
