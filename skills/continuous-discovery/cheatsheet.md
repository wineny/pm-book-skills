# 치트시트 — 『컨티뉴어스 디스커버리 해빗』 판단 규칙

> 용어 정의는 glossary, 절차는 patterns. 여기는 **저자가 그 상황에서 어떻게 결정하는가**만.

## 1. 성과 고르기 (Ch 3)

| 상황 | 결정 | 이유 |
|---|---|---|
| 팀에 지표를 배정한다 | 비즈니스 성과 말고 **제품 성과** | 팀이 움직일 수 있는 범위 안이어야 방향이 잡힘 |
| 지표가 후행(재구매·리텐션)이다 | 그걸 예측하는 **선행 지표**로 바꿔 배정 | 후행 지표는 팀을 사후 대응 위치에 놓음 |
| "목표로 가는 중간 행동"을 지표로 걸고 싶다 | 그 행동이 **특정 산출물의 존재를 전제**하면 산출물이다 → 걸지 마라 | 전환 캘린더 참여도 = 캘린더라는 산출물에 매달린 것 |
| 위 예외 | 고객이 그 행동을 원한다는 게 **이미 디스커버리로 확인**됐을 때만 | 디스커버리 질문이 답이 나온 상태 |
| 특정 워크플로 사용량 지표 | **트랙션 지표** — 검증된 성숙 기능 최적화 때만 | 새 솔루션을 찾는 단계에 걸면 솔루션이 미리 좁혀짐 |
| 성과를 처음 받았다 | **학습 목표**("효과 있을 전략 찾기") 먼저, S.M.A.R.T.는 전략이 잡힌 뒤 | 전략 없는 도전적 목표는 성과를 오히려 떨어뜨림 |
| 팀이 경험이 적다 | 트랙션 지표부터 | 통제 범위가 작아야 학습이 붙음 |
| 지표를 바꾸고 싶다 | 몇 분기 머물러라 | 바꿀 때마다 학습 세금 |
| 지표가 하나면 불안 | 주 성과 + **건강 지표** 짝 | 확보 ↔ 만족도처럼 부작용 감시 |

## 2. 기회 칸에 넣을지 판정 (Ch 5·6)

- **솔루션이 아닌가?** → "해결 방법이 하나보다 많은가?" 하나뿐이면 솔루션. 빼라.
- **고객 관점인가?** → "인터뷰에서 이런 말을 들었나?" / "고객이 이렇게 말하는 걸 상상할 수 있나?" 우리가 그렇게 말해 주길 *바라는* 문장이면 탈락.
- **여러 고객인가?** → 한 명만 말했으면 인사이트 칸에 두고 기다려라.
- **성과로 이어지나?** → 아니면 트리에 안 올린다. 모든 기회를 해결하는 게 일이 아니다.
- **감정인가?** → 감정("답답하다")은 고칠 수 없다. 원인을 찾는 이정표로만.
- **자식이 하나뿐인 사슬**이면 중복 표현이거나 형제 누락. **부모가 둘**이면 너무 넓은 것 → 순간별로 쪼개라.
- 번호는 우선순위가 아니라 **경험 지도의 시간 순**.
- 트리가 30분에 끝났으면 덜 생각한 것, 몇 시간째 완벽을 다투면 과한 것.

## 3. 타깃 기회 고르기 (Ch 7)

- "이 기회를 할까 말까?" 라고 묻고 있으면 **멈춰라** → 형제 기회끼리 **비교·대조**로 바꿔라.
- 4렌즈: 규모(몇 명 × 얼마나 자주) · 시장(기본 요건 vs 차별화) · 회사(전략·강점·정치) · 고객(중요도 높고 만족도 낮은 것). **점수 매겨 줄 세우지 마라** — 대화 도구다.
- 한 번에 **리프 노드 하나**. 리프 = 쉽다는 뜻이 아니라 아직 하위 기회를 못 찾았다는 뜻.
- 결정은 한두 시간, 길어도 하루 이틀. 양방향 문이다 — 되돌릴 수 있으니 빨리 정하고 계속 의심하라.
- 데이터 더 모일 때까지 미루지 마라 — 테스트에서 더 배운다.

## 4. 솔루션·아이디어 (Ch 8)

| 규칙 | 숫자 |
|---|---|
| 타깃 기회당 아이디어 | **15~20개** |
| 솔루션 세트 | 성격이 다른 **3개**(하나로 좁히지 마라) |
| 점 투표 | 1인 **3표**, 배분 자유, 기준은 "타깃 기회를 얼마나 잘 해결하나"뿐 |
| 투표 전 필터 | 타깃 기회를 전혀 해결 못 하는 것 제거(부분 해결은 통과) |
| 생성 vs 평가 | 생성은 **혼자**, 평가는 **그룹** |

- 기회마다 솔루션 하나씩 달고 있으면 트리가 아니라 백로그다. 비교는 솔루션들 사이에서.
- 사자→호랑이→퓨마식 변형 남발이면 범주가 다른 아이디어를 의도적으로 찾아라.

## 5. 가정 (Ch 9)

- 아이디어를 테스트하지 말고 **가정**을 테스트하라. 단순한 아이디어도 **20~30개**.
- 표현: **긍정형**("고객은 X할 것이다") + **구체형**(어느 화면에서 무엇을). 부정형·"시간이 있을 것이다"는 테스트 불가.
- 5범주 체크: 매력도(원하나) · 사업성(만들어야 하나) · 실현성(만들 수 있나) · 사용성(쓸 수 있나) · 윤리성(해악은). 사용성을 매력도로 착각하지 마라 — 쓰기 편함 ≠ 원함.
- 가정 매핑: x=근거 양, y=중요도. **오른쪽 위 2~3개**만. 아이디어당 10분.
- 프리모템은 **확정형**으로: "실패했습니다. 왜?" ("실패할 수도"는 효과 없음)
- 이미 한 번 실패한 가정은 **맨 위 오른쪽**이다 — 자기 과거 데이터부터 뒤져라.

## 6. 테스트 설계 (Ch 10)

| 규칙 | 기준 |
|---|---|
| 평가 기준 | **결과 보기 전에**, "N명 중 최소 M명" (인원 수 두 개) |
| 퍼센트 | 금지 — "70%"는 6명 결과에서 실패냐 재테스트냐로 갈림 |
| 첫 라운드 | 1~2일, 길어도 일주일. 시뮬레이션하되 만들지 마라 |
| 인원 | 팀이 "몇 명이면 납득하나"로 협상. 적게, 그러나 행동할 만큼 |
| 질문 | 미래 의향(×) → 과거 행동·구체 기간(○) |
| 대상 | 그 기회를 실제로 겪는 사람. 접근 쉬운 사람만(×) |
| 설계 편향 | 적은 인원일 땐 **통과하기 쉽게** 설계 — 최선 조건에서 실패해야 결과가 덜 모호 |
| 사다리 | 초기 신호 → 큰 실험. 멈추는 조건: 위험 충분히 제거 or 다음 테스트가 만드는 것보다 비쌈 |

- 거짓 양성은 다음 라운드에서 드러나고, 거짓 음성은 다양성 모집으로 완화. 둘 다 대규모 실험으로 시작할 이유는 못 된다.

## 7. 측정·사이클 (Ch 11·12)

- 제품 성과가 올랐다 ≠ 비즈니스 성과가 오른다. **별개 가설**로 계측하라. 안 이어지면 새 제품 성과를 찾아라.
- 단일 선행 지표가 움직였다고 판정하지 마라(검색 시작 36→83%인데 지원 전환은 하락).
- 사람 수 vs 횟수: "한 사람이 여러 번 = 여러 사람이 한 번씩"인가? 아니면 사람 수.
- 테스트가 "고객이 우리 도움을 원치 않는다"를 드러내면 → 트리로 돌아가 **새 타깃 기회**. 처음부터가 아니다(화요일 접고, 수요일 고르고, 목요일 이미 잡힌 인터뷰).
- 결실 없는 기회엔 **일주일**만.

## 8. 공유·시작 (Ch 13·14)

- 결론(로드맵)이 아니라 **과정**을, 트리 **맨 위부터**: 성과 → 상위 기회 → 왜 이걸 골랐나 → 솔루션 3개 → 테스트. CEO에게도 이 뼈대는 뺀 안 된다.
- 상대 아이디어 분기: 다른 성과 → "그 성과엔 맞다" / 다른 기회 → 아이디어 백로그 / 우리 기회 → 함께 스토리 맵·가정 도출.
- 하나만 시작한다면 **지속적 인터뷰**(핵심 습관). 주 1회, 5분이어도 됨. 고객 못 만나면 비슷한 처지 아무나부터.
- 지시받은 기능은 **거꾸로 일하기**: "고객에게 어떻게 도움?"(함축된 기회) + "사업에 어떤 가치?"(함축된 성과) = 첫 트리.
- 디스커버리 옹호 최적 타이밍 = 기능이 기대에 못 미쳤을 때. "그럴 줄 알았다"는 금물.

## 9. 냄새 (tells)

- "돕기가 목표야 수단이야"로 회의가 헤맨다 → **기회 층이 비었다**.
- 기회 다섯 개가 "시작 전·진행 중·신청 전"처럼 층이 섞여 있다 → 경험 지도(4장)를 안 그렸다.
- 기회 근거가 전부 로그·회의록·내 관찰이다 → 인터뷰 0건. 「실측」이라 부르지 마라.
- "이거 할까 말까?" → 할지 말지 결정. 형제와 비교하라.
- 솔루션 목록이 기회 수 × 1개다 → 백로그. 하나에 3개 이상.
- 가정 테스트 0건인데 목표를 80%로 걸었다 → 학습 목표 단계다.
